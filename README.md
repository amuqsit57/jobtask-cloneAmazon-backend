# Amazon Clone — Backend API

REST API for the Amazon rebuild. Node, Express, Postgres (Neon), JWT auth.

**Frontend repo:** [jobtask-cloneAmazon-frontend](https://github.com/amuqsit57/jobtask-cloneAmazon-frontend)

---

## Running locally

```bash
npm install
cp .env.example .env      # fill in DATABASE_URL and JWT_SECRET
npm run migrate           # create the schema
npm run seed              # load the catalog
npm run dev               # http://localhost:4000
npm test                  # 41 assertions across every flow
```

`npm run seed` is idempotent — it rebuilds the catalog but leaves accounts and
orders alone, so a reseed during development does not sign everyone out. Pass
`--reset` to wipe everything including accounts.

Demo account created by the seed: `demo@example.com` / `Password123!`

## Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/health` | — | Liveness plus a DB round-trip and product count |
| GET | `/api/products` | — | Search, filter, sort, paginate |
| GET | `/api/products/suggest` | — | Header search suggestions |
| GET | `/api/products/featured` | — | Home page rails |
| GET | `/api/products/:slug` | — | Detail, images, variants, reviews, related |
| GET | `/api/categories` | — | Categories with product counts |
| POST | `/api/auth/register` | — | Create account, returns JWT |
| POST | `/api/auth/login` | — | Sign in, returns JWT |
| GET | `/api/auth/me` | JWT | Resolve current user |
| GET | `/api/cart` | optional | Cart for user or guest session |
| POST | `/api/cart/items` | optional | Add to cart |
| PATCH | `/api/cart/items/:id` | optional | Change quantity, save for later |
| DELETE | `/api/cart/items/:id` | optional | Remove line |
| POST | `/api/cart/merge` | JWT | Fold a guest cart into the user's |
| GET | `/api/orders` | JWT | Order history |
| GET | `/api/orders/:orderNumber` | JWT | Single order |
| POST | `/api/orders` | JWT | Place order from cart |
| GET/POST | `/api/addresses` | JWT | Saved addresses |

Guest carts are keyed by an `x-cart-session` header.

## Design decisions

**Money is integer cents everywhere.** Floating-point money is the classic
e-commerce bug: `0.1 + 0.2 !== 0.3`, and it surfaces as a cart total a penny off
after a few line items. Formatting happens once, server-side, so every surface
renders currency identically.

**Orders snapshot what was bought.** `order_items` stores the title, image and
unit price at purchase time. An order must always render what the customer
actually bought at the price they actually paid, even after the product is edited,
repriced or deleted.

**Order placement is one transaction.** Prices are re-read from the products
table rather than trusted from the client, stock is checked and decremented, line
items are written and the cart is emptied. Any failure rolls the whole thing back,
so there is never an order with no stock movement or a half-emptied cart.

**Search is Postgres, not a search service.** A generated `tsvector` column with a
GIN index, weighted title > brand > description, with `ts_rank` relevance
ordering. Fast enough at this scale and one less moving part to deploy.

**Login does the same work whether or not the account exists.** A missing user
still runs a bcrypt comparison against a dummy hash, so response timing does not
reveal which emails are registered.

## Deploying to Render

`render.yaml` defines a free-tier web service. Set in the dashboard:

- `DATABASE_URL` — Neon connection string
- `CORS_ORIGIN` — deployed frontend URL (comma-separated for several)

`JWT_SECRET` is generated by Render. The health check at `/api/health` also gives
the sleeping free-tier instance something cheap to wake on.

**Note on the free tier:** the instance sleeps after 15 minutes idle and takes
~30 seconds to wake. The frontend home page degrades to an explanatory shell
rather than a 500 while that happens.
